# knowledge-base-demo

A demo knowledge base built with [eru](https://github.com/dburriss/eru), following
[Set up a knowledge repo](https://github.com/dburriss/eru/blob/main/docs/how-to/set-up-a-knowledge-repo.md),
with curation run by a [GitHub Agentic Workflow](https://github.com/github/gh-aw).

## Adding knowledge: how inbox ingestion works

1. Register this repo as a remote inbox, then send it a note, file, or URL:
   ```bash
   eru inbox add kb git@github.com:dburriss/knowledge-base-demo.git
   eru inbox send "note" -i kb
   ```
2. Wait a few minutes. The ingestor agent curates your item into an OKF note and merges it
   automatically; there's nothing to push or review.
3. View your curated notes: start at [`index.md`](index.md), or browse the topic folders
   (e.g. [`software-engineering/`](software-engineering/)). Your original item is kept in
   `inbox/archive/`. The same notes are published as a [website](#generated-site).

Locally, `eru inbox process -i kb` does the same via the `default` channel (`copilot --acp`).

## Generated site

The curated notes are published as a static site at
**<https://devonburriss.me/knowledge-base-demo>**, generated by `eru site generate`. It has a
browsable file list, per-tag pages and in-page search. Everything is plain HTML, with JavaScript
only for search and filtering.

### How it's built

- **Source.** The repo is registered as an eru source (`kb`) in [`.eru/config.json`](.eru/config.json),
  with an OKF bundle at the repo root. Eru discovers the notes by walking the tree and reading each
  file's frontmatter, so no `.eru/manifest.json` is needed. This relies on the root
  [`index.md`](index.md) carrying `okf_version`, which is what marks the repo as an OKF bundle.
- **Scope.** `siteIgnorePatterns` in the same config keeps `inbox/`, `apm_modules/`, `.agents/`,
  `.claude/` and `.github/` out of the site, so only curated notes appear.
- **Workflow.** [`.github/workflows/pages.yml`](.github/workflows/pages.yml) installs eru (pinned to a
  version), runs `eru sync` and `eru site generate -o _site`, then deploys with
  `actions/deploy-pages`. It runs:
  - on pushes to `main` that change a `.md` file, `.eru/config.json` or the workflow itself;
  - after **Automerge ingest PRs** completes successfully. Ingest PRs are merged with
    `GITHUB_TOKEN`, and pushes made that way don't trigger other workflows, so this is what
    republishes the site after each ingest;
  - manually, with **Run workflow** (`workflow_dispatch`).
- **Hosting.** Pages deploys from Actions, so there is no `gh-pages` branch. Enable it once under
  Settings → Pages → Build and deployment → Source: **GitHub Actions**.

### Keeping the bundle valid

The site only reflects notes that eru can read as an OKF bundle. After changing notes or indexes by
hand, check and repair them:

```bash
eru okf validate .   # report violations
eru okf fix .        # repair them (use --dry-run to preview)
```

To preview the site locally, run `eru sync` and then `eru site generate --open`. Run it from this
repo so it picks up the `kb` source.

## Use it as a knowledge base for agents

Any project can query these notes from an AI agent. Register this repo as a source once, then
give the agent either the eru MCP server or the eru CLI with its skill.

### 1. Register the source

```bash
dotnet tool install --global Eru.Tool
eru source add https://github.com/dburriss/knowledge-base-demo --name kb --scan --global
eru sync
```

`--scan` finds the OKF bundle at the repo root (the `okf_version` in [`index.md`](index.md)), so no
manifest is needed. `--global` makes the source available to every project; leave it off to register
it only in the current repo's `.eru/config.json`. Run `eru sync` again to pick up new notes.

### 2a. Via MCP

`eru mcp` is a stdio MCP server that exposes the knowledge as tools and resources. Add it to the
client config, for example `.mcp.json` for Claude Code (this repo's own [`.mcp.json`](.mcp.json) is an
example, and [`.github/mcp.json`](.github/mcp.json) is the Copilot equivalent):

```json
{
  "mcpServers": {
    "eru": { "command": "eru", "args": ["mcp"] }
  }
}
```

| Tool | Use |
|---|---|
| `search_knowledge` | Search by terms (any match) and tags (all must match); returns paths, tags, descriptions and excerpts |
| `read_artifact` | Read a note, e.g. `kb:software-engineering/choose-boring-technology.md` |
| `refresh_knowledge` | Re-sync the sources without restarting the server |

The server also lists sources as resources (`eru://sources`). It re-syncs in the background every 60
minutes by default (`mcpRefreshIntervalMinutes` in the eru config).

### 2b. Via the CLI and a skill

Without MCP, the agent can run the eru CLI itself. Install the eru skill so it knows the commands.
With apm, add this to the consuming project's `apm.yml` and run
`apm install` (as this repo does):

```yaml
dependencies:
  apm:
    - dburriss/eru/skills/eru
```

The agent can then run commands like:

```bash
eru search diataxis                 # find notes by term; add -t <tag> to filter
eru source files kb                 # list everything the source publishes
eru add kb:documentation/diataxis.md   # copy a note into the project and track it in .eru/eru.lock
eru sync                            # refresh pulled files and the search index
```

Use MCP when the agent only needs to look things up. Use the CLI when you want notes pulled into the
project as tracked files, so they are versioned with it and refreshed by `eru sync`.

## Setup

Find the detailed setup instructions here: [Generate docs from inbox changes with a GitHub Agentic Workflow](https://github.com/dburriss/eru/blob/main/docs/how-to/generate-docs-from-inbox-with-gh-aw.md)

```bash
mise install          # apm, dotnet, ck
dotnet tool install --global Eru.Tool
apm install           # skills + ingestor agent + eru MCP
gh aw compile         # after editing .github/workflows/*.md
```

The workflow uses gh-aw's `copilot` engine; add the `COPILOT_GITHUB_TOKEN` repo secret (`gh aw secrets`).

The inbox `kb` is registered in `.eru/config.json` (repo-local), or a global to allow sending notes from anywhere. If you have a single inbox, you can drop the inbox flag `-i kb`.
