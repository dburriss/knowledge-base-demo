# Diátaxis

Diátaxis is a systematic approach to technical documentation authoring: a way
of thinking about and doing documentation, derived from understanding what
documentation users need.

## The four needs and forms

Diátaxis identifies four distinct user needs and a corresponding form of
documentation for each:

| Need | Form |
|---|---|
| Learning | Tutorials |
| Accomplishing a task | How-to guides |
| Looking up facts | Technical reference |
| Understanding | Explanation |

The forms are placed in a systematic relationship, and the framework proposes
that documentation should itself be organised around the structures of these
needs.

## What it addresses

- **Content**: what to write.
- **Style**: how to write it.
- **Architecture**: how to organise it.

It is light-weight and imposes no implementation constraints. It also helps
creators and maintainers by giving them an active principle of quality for
their own work. The site reports adoption in hundreds of documentation
projects (e.g. Vonage, Gatsby, Cloudflare developer docs).

## Use in this knowledge base

The `type` field of notes here (`tutorial`, `how-to`, `reference`,
`explanation`) follows these four modes.
